Clases

Una libreria Luau para Roblox que convierte el patron normal de metatables en un sistema de objetos con lifecycle, tipado practico, cleanup, herencia y tooling serio.

Ver tipado GitHub
typed-counter.luau
local Clases = require(game.ReplicatedStorage.Shared.Clases)

export type Counter = Clases.Object & {
	value: number,
	add: (self: Counter, amount: number) -> number,
}

export type CounterClass = Clases.Class<Counter> & {
	new: (value: number) -> Counter,
}

local Counter = Clases.define("Counter", {
	constructor = function(self: Counter, value: number)
		self.value = value
	end,

	methods = {
		add = function(self: Counter, amount: number): number
			self.value += amount
			return self.value
		end,
	},
}) :: CounterClass

Que resuelve

Lifecycle real

Constructores, destructores, `Destroy` idempotente y cleanup LIFO sin reescribirlo en cada clase.

Herencia limpia

`extend`, `super`, `IsA` y ancestros precomputados. Sin herencia multiple rara.

Tipado honesto

`Clases.Object` y `Clases.Class<T>` para declarar objetos estrictos sin fingir inferencia magica.

Tipado

El patron recomendado es declarar el tipo de instancia, declarar el tipo de clase y castear `Clases.define` una vez. Asi Luau sabe que metodos existen y que devuelve `new`.

Patron recomendado
export type Door = Clases.Object & {
	part: BasePart,
	open: (self: Door) -> (),
}

export type DoorClass = Clases.Class<Door> & {
	new: (part: BasePart) -> Door,
}

local Door = Clases.define("Door", {
	constructor = function(self: Door, part: BasePart)
		self.part = part
	end,

	methods = {
		open = function(self: Door)
			print("open", self.part.Name)
		end,
	},
}) :: DoorClass

Usa `Class.new(...)` cuando quieras que Luau revise los argumentos del constructor. `Class(...)` tambien funciona, pero sus argumentos son genericos.

Cleanup

Clases limpia conexiones, instancias, funciones, threads y objetos con metodos conocidos.

Conexion Roblox
constructor = function(self, button: TextButton)
	self:addCleanup(button.MouseButton1Click:Connect(function()
		self:onClicked()
	end))
end
Recurso custom
self:addCleanup(part)
self:addCleanup(function() print("done") end)
self:addCleanup(resource, "Stop")

self:Destroy()

Herencia y mixins

Herencia para identidad; mixins para capacidades.

Herencia
local Animal = Clases.define("Animal", {
	methods = {
		speak = function(self)
			return self.name
		end,
	},
})

local Dog = Animal:extend("Dog", {
	methods = {
		speak = function(self)
			return `{self:super("speak")} bark`
		end,
	},
})

Los mixins copian metodos. Si dos mixins chocan en el mismo metodo con funciones distintas, la clase falla al definirse.

FAQ corto

Es mas rapido que una clase manual?

Las llamadas de metodo quedan muy cerca del patron manual. Crear, destruir, `super` e `IsA` tienen coste extra porque agregan lifecycle e introspeccion.

Reemplaza Trove?

No siempre. Cubre el cleanup normal de una instancia. Puedes registrar Trove si necesitas su API completa.

Debo usarlo para todo?

No. Usalo para objetos con estado y ciclo de vida; no para tablas de configuracion o funciones puras.
